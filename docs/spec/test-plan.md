# テスト計画(ステップ1:記録と来歴)

- 版:初版(2026-09-26)。issue #22。
- 位置づけ:V字の右側。設計の各段階に対応するテストで、何をどう確かめるか。要件(`requirements.md`)・外部設計(`external-design.md`)・内部設計(`internal-design.md`)との対応表を含む。
- 根底は「交流と交換」で、記録はそれを効果的に実現するためのもの(`requirements.md` 0章)。受入テストでは、機能が動くことに加えて、交流・交換に役立つかも確かめる(5章)。

## 1. 考え方
| 設計(左側) | テスト(右側) | 確かめること | 主な方法 |
|---|---|---|---|
| 要件整理 | 受入テスト | 要件を満たすか。判定点(4か月目)の基準を満たすか | ローカルでの操作確認、実機(自分+テスター)、集計 |
| 外部設計 | システムテスト | 画面の流れと機能が、設計どおりに動くか | ウィジェットテスト・統合テスト、ローカル実行(Web)での確認手順 |
| 内部設計 | 結合テスト | 層どうし・サーバーとの連携が、設計どおりか | 権限ルールのテスト(エミュレーター)、保存先とのテスト、サーバー処理の通しの確認 |
| 実装 | 単体テスト | 関数・クラスの動き | `flutter test`(domain・data)、`functions` の単体テスト |

- 日々の確認はローカルで行い、実機は節目だけ(6章)。ローカルで確かめた場合は、端末固有の動きを未確認であることを PR に書く(`dev-rules.md` 2章)。
- 権限ルールを変えたら、「見えてはいけないものが見えない」テストを必ず追加し、全件合格を確かめる(REQ-044)。

## 5. 4か月目の判定に使う数字(受入・FN-25)
判定点は `docs/project/evaluation.md` 5章。ステップ1の判定の基準は「自分が続けている」「テスターの半数以上が4週後も週1回以上撮影」「テスターが来歴記録を『取引で見せたい』と答える」「セキュリティのフェーズ1必須項目を満たす」。

### 5.1 記録のデータから数えるもの
| 数字 | 数え方 | 使う場所 |
|---|---|---|
| 週1回以上撮影した人の割合 | 各ユーザーの `photos.receivedAt`(サーバー時刻)を週ごとに数える。4週後の週に1枚以上あるか | 判定の基準 |
| 1人あたりの撮影した株の数・写真の枚数 | 株ごとの `photos` の件数 | 継続の確認 |
| 来歴つきの写真の割合 | `provenance` が真の写真 ÷ 全写真 | 来歴が実際に成立しているかの確認 |
| 水やりの記録の件数 | `logs`(`type == water`)の件数 | 「水をやった」1タップが使われているか |
| 通知をオンにした人の割合 | `users.notify.photo` / `water` が真の人 ÷ 全員 | オプトインの実態(REQ-030〜032) |
| (後回し)巡回モードで1回にかかった時間 | 巡回モードを戻したときに、巡回の開始から完了まで(自分で計る) | 手間の確認 |

- 集計は、開発者だけが管理者の権限で行う(アプリからは行わない)。個人が特定される形で外に出さない。Analytics を使う場合は、同意とプライバシー表示を決めてから(内部設計 7章6)。

### 5.2 テスターに聞くこと(根底の確認を含む)
`docs/project/concept.md` 末尾の質問リストのうち、ステップ1で聞くもの。根底(交流と交換)に関わるものを先頭に置く。
1. 自分の記録を、誰かに見せたいか。見せるとしたら、どの範囲(写真のみ/履歴まで/入手先まで)までか。
2. 相手の記録・来歴が見えたら、取引・交換で安心できるか。自分の記録を「取引で見せたい」か。
3. 記録を公開するのに、盗難などの不安はあるか。どうなら安心か。
4. 株や資材を交換したい・譲りたいことがあるか。あるとき、今はどうしているか。
5. 手持ちの株に来歴が付かない(アプリを入れた後の株だけが対象)ことを、どう感じるか。
6. アプリ内カメラでしか来歴にならないことを、受け入れられるか。
7. 定期通知は欲しいか(初期オフ)。「水をやった」1タップなら使うか。
- 聞き取りの結果は、`decisions.md` の未決事項に反映する。

## 8. 「見えてはいけないものが見えない」テスト
権限ルールを変えたら追加する(REQ-044)。現状と、これから追加するもの。

### 8.1 済み(Firestore・Storage のルールのテスト)
| 見えてはいけないもの・できてはいけないこと | テスト |
|---|---|
| 他人が、自分のユーザー情報を読む | 「他人は読めない」「ログインしていない人は読めない」 |
| 他人が、自分の非公開の株を読む・一覧にする・書き込む | 「他人は非公開の植物を読めない」「他人は植物の一覧を取得できない」「他人の植物リストに書き込めない」 |
| 公開の説明を確認する前に、公開用データが書き出される | 関数のテスト「確認日時がなければ書き出さない」。ルールのテスト「確認日時を偽れない・後から変えられない・他人のものを書けない」(#58) |
| 他人が、記録を読む・書く | 「他人は記録を書けない・読めない」 |
| 他人が、写真の記録・来歴の欠落の記録を読む | 「他人は写真の記録を読めない」「他人は来歴の欠落の記録(systemLogs)を読めない」 |

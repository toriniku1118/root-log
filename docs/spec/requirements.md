## 0. 根底:交流と交換(2026-09-26、ユーザー決定)
このサービスの根底は「交流と交換」。ハマっている人どうしが、記録を見せ合い、イベントや取引で株・資材を交換し、交流する。成長記録と来歴は、交流と交換を**効果的に実現するための記録**(相手を知る手がかり・話のきっかけ・信頼・見せる素材)であって、記録そのものが目的ではない。ステップ1が「記録と来歴」なのは、交流・交換の前に、見せられるもの・信頼されるものが要るため。

**作り込む中核は3本(2026-09-26、ユーザー決定):「記録」「交換・売買」「交流」。** 記録も重要だが、**記録の作りはシンプルでよい**。記録機能を作り込みすぎず(記録アプリとして完結する方向に広げない)、手間は交換・売買と交流を効果的にする部分にかける。ステップ1の記録機能のうち、ゴースト表示・タイムラプス・巡回モードは後回しと決めた(2026-09-26、#33)。ただし、タイムラプスなどを自分で作れるよう、写真はすべてダウンロードできるようにする(REQ-046)。写真のダウンロードの形は決定済み(Q11)。撮影後の比較・段階・「いつもの間隔」は残す(Q10 決定済み)。

**対象と、はじめの形(2026-09-26、ユーザー決定)。** 対象は、観葉植物を育てている、初心者から少し踏み込んだ層以上(年齢層は特定しない)。株が増え、余る資材・欲しい資材・売りたい植物がある人が、相手の背景(記録)を見ながら売買・交換でき、病気や困りごとを相互に相談できる場を目指す。ただし、**はじめは記録アプリから作る**。ステップ1は、水やり・鉢替え(植え替え)・その他の記録・コメント(メモ)など、一般的な記録が中心(REQ-022〜025)。有料プランの記録共有(カップル・夫婦・家族)と、相談Q&A(すべて無料)は、後のステップ。

要件を決めるとき・優先度を付けるときは、次を確かめる。
1. その要件は、交流・交換を効果的にするために、どう役立つか(下の表)。役立たないなら、なぜ今作るのかを書く。
2. 記録アプリとして完結する方向(記録機能の作り込み、AIによる世話の支援など)に寄りすぎていないか。
3. 文言・画面が、「記録すること」ではなく「見せ合える・交換できること」の価値を伝えているか。

## 1. 優先度と状態の見方

### 優先度(実装の順序)
`dev-rules.md` 3章のとおり、1画面を作り込む前に全画面の機能をつなぐ。その順序を優先度にした。

| 優先度 | 意味 | 確かめ方 |
|---|---|---|
| P1 | 縦串。Firebase につながず(メモリ上の保存先で)、全画面をつなぐ | `flutter test`・Web のローカル実行 |
| P2 | 接続。Firebase(エミュレーター)につなぎ、サーバー処理と合わせて動かす | エミュレーター+`flutter test` |
| P3 | 端末に依存する機能(カメラ・撮影時刻・通知・サインイン)と、節目の作業 | 実機(`dev-rules.md` 2章) |
| 常時 | 作業のたびに守る決まり | レビュー・自動テスト |

### 状態
| 状態 | 意味 |
|---|---|
| 実装済み | 実装があり、自動テストで確かめてある |
| 一部 | 一部だけ実装済み。何が済んでいて何が残っているかを備考に書く |
| 未 | まだ作っていない |
| 後回し | ステップ1では作らないと決めた(設計は残す)。優先度・実装の順序から外す。必要になったら、先にこの書類を直して戻す |

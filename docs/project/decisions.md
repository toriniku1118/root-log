# 植物アプリ(仮名:RootLog)開発の決め事(2026-09-25)

アプリを作るうえで確定した事項の一覧。変更したら日付とともにここを更新する(直近の更新:2026-09-26)。詳細は「植物アプリ_コンセプト」「植物アプリ_セキュリティ要件」「植物アプリ_総合評価_2026-09」「植物アプリ_市場規模と収益見通し_2026-09」。

## 1. 確定事項
### 方針・対象
| 項目 | 決め事 |
|---|---|
| 最優先 | セキュリティ要件を、機能の追加・納期よりも優先する |
| 根底 | このサービスの根底は「交流と交換」(2026-09-26)。成長記録・来歴は、交流と交換を効果的に実現するための記録であり(見せ合い、相手を知る手がかり、取引での信頼)、記録そのものが目的ではない。機能・順序・文言は、交流・交換を効果的にしているかで判断する。収益(有料プラン・手数料など)は、この根底を支えるための手段 |
| 対象 | 観葉植物に「ハマっている層」(塊根・アガベ・ビカクシダ・珍奇植物・アロイド・実生など) |
| 形 | 植物専用のアプリ(汎用フリマではなく、あえて専用) |
| 検証 | LINEオープンチャット等の手作業の実験はしない。プロトタイプを作り、自分で運用して課題を抽出 |
| 働き方 | 1年は副業、その後は本業の想定(専業化は判断基準を満たした場合) |

### 機能
| 項目 | 決め事 |
|---|---|
| 成長記録 | 植物リスト、タイムラプス的な写真管理、栽培ストーリー、ジャンル分け。水やりは「水をやった」ボタンで1タップ登録するのが基本。定期通知(撮影・水やり)は初期オフで、本人が希望した場合のみ(2026-09-26) |
| 来歴記録 | アプリ内カメラで撮った写真だけを来歴として扱い、撮影日時を後から変えられない形にする |
| 共有 | 記録の公開は本人が選ぶ(任意・初期は非公開)。公開すると売買・交換・レスキューでの信頼材料になり、他の SNS などで引用して見せられる。公開プロフィールに SNS・YouTube のリンクを載せられる(任意・初期は非公開。2026-09-26)。同居人との共有は有料プラン |
| 売買・交換 | 記録を公開している人だけが使える。相手の記録・来歴を見て取引できることが差別化。資材も対象。弱った株・不要な株は「レスキュー株」区分 |
| 取引の方式 | 固定価格と交換のみ。入札(オークション)形式にはしない。代金は自分で預からず、決済代行サービスを使う |
| コミュニティ | 入荷情報(レア植物の販売場所の共有)、相談Q&A(知恵袋の観葉植物版)、イベント(関東・関西から→全国、会場での交流・交換、周辺店舗への送客) |
| イベント・入荷情報の提供 | 当初は無料。情報の収集は生成AIで行い、確度の高い情報だけを載せる(出典リンクと確認日つき)。店・主催者への有料掲載は、関心を確認してから(後回し)(2026-09-26) |
| 通知 | 全種類あわせて原則1日1回まで。通知の許可は最初の撮影のあとに求める。撮影通知・水やり通知はどちらも初期オフで、希望した人だけオンにする(2026-09-26。聞き取りで「定期通知は面倒」という声) |
| 盗難対策 | 公開する地域は都道府県まで。株の価格・コレクションの規模は初期設定で非公開 |

### 開発の順番
- 来歴記録(ステップ1)→ 入荷情報とイベント、6か月目ごろにストア公開(ステップ2)→ 記録を見せ合う(ステップ3)→ 有料プラン(ステップ4)→ 売買・交換(ステップ5)→ 拡大(ステップ6)。その前にステップ0(準備)。
- 「相手の記録を見られる機能」を売買より先に作る。
- 当面(2026-09-26 決定)は、ステップ1の生育記録(機能)の作りこみを優先する。見た目は作り込まず、ワイヤーフレーム方針(`docs/dev-rules.md` 3章)のまま、全画面の機能を先につなぐ。店・主催者への確認、競合との比較は後回し。SNS の投稿量の調査は保留。

### 収益
| 項目 | 決め事 |
|---|---|
| 収益の柱 | 有料プランと取引(手数料・出品オプション)。広告は補助 |
| 有料プラン | 月480円 |
| 売買手数料 | 5% |
| 出品オプション | 1回200円 |

### 開発の技術・基本設定・運用(2026-09-25 決定)
| 項目 | 決め事 |
|---|---|
| 開発の技術 | Flutter+Firebase |
| 対象OS | iOSとAndroidを同時に出す |
| 開発環境 | Ubuntu PC+Docker(Flutter・Android SDK のコンテナ、Firebase エミュレーターのコンテナ)。Android は USB でつないだ実機で開発 |
| iOS のビルド | Linux ではビルドできないため Codemagic(macOS のクラウドビルド。個人は月500分無料)でビルドし、TestFlight で自分の iPhone に配布。iOS 固有の不具合の調査で必要になったら Mac の購入・レンタルを検討 |
| ログイン | Appleでサインイン、Googleでサインイン(メールアドレスでのログインは用意しない) |
| 最初に扱うジャンル | 観葉植物全般(パキラ・モンステラ・ポトス等)+ハマっている層の主要ジャンル:塊根・アガベ・多肉/サボテン・ビカクシダ・アロイド・珍奇植物・実生(+その他) |
| アプリ名(仮) | RootLog(ルーツログ)。「根(root)」と「来歴(ルーツ)」の掛け言葉。正式名はストア公開前(ステップ2)に商標・同名アプリを確認して決める |
| 副業規定 | 勤務先の副業規定に問題がないことを確認済み |
| 年齢 | 13歳以上が利用可能。売買・交換・手渡しは18歳以上に限定 |
| 写真の保存 | 枚数は無制限。無料プランは画質を圧縮して保存(長辺1600px程度)、有料プランで高画質 |
| 広告・利用分析 | AdMob+Firebase Analytics(広告は補助。プライバシー表示・同意取得はセキュリティ要件9章に従う) |
| テスターの集め方 | Xで募集(開発の様子を発信しながら)+知人・友人 |

## 2. 未決事項
### 2026-09-26 に出たもの
- **判定点の指標**:8か月目の判定点「入荷情報の投稿が関東・関西で週10件以上」(`evaluation.md` 5章)は、生成AIで収集する形になったため、指標を読み替えるか決める(例:掲載件数と、誤情報の報告の割合)。
- **AI 収集の仕組み**:元にする情報源の範囲、確度の判定方法、費用の上限、間違いがあったときの訂正の流れ。ステップ2の設計で決める。
- **リンクの許可ドメイン**:載せられるサービスの一覧(Instagram・X・YouTube など)。ステップ3の設計で決める。
- **引用時の画像の印**:公開した記録を他の SNS で引用するとき、画像に株のページへたどれるリンクや QR を付けるか(写真の使い回しへの対策)。ステップ3以降で検討。
- **聞き取りで確認できていないこと**:手持ち株に来歴が付かないことへの受け止め、盗難への不安、「取引のためなら公開する」人の割合、来歴つきの株に買い手が高く払うか、入荷通知に月480円払うか、親株の持ち主による確認(親子リンク)への反応。
- **後回し・保留**:店・主催者の関心の確認、NextMeet・GreenSnap・成長記録カメラとの比較(後回し)。X・Instagram・LINE の投稿量の調査(保留)。ストア公開前(ステップ2の前)までに、再開の時期を決める。

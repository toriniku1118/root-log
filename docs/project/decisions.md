## 1. 確定事項

### 機能
| 項目 | 決め事 |
|---|---|
| 成長記録 | 植物リスト、タイムラプス的な写真管理、栽培ストーリー、ジャンル分け。水やりは「水をやった」ボタンで1タップ登録するのが基本。定期通知(撮影・水やり)は初期オフで、本人が希望した場合のみ(2026-09-26) |
| 来歴記録 | アプリ内カメラで撮った写真だけを来歴として扱い、撮影日時を後から変えられない形にする |
| 共有 | 記録の公開は本人が選ぶ(任意・初期は非公開)。公開すると売買・交換・レスキューでの信頼材料になり、他の SNS などで引用して見せられる。公開プロフィールに SNS・YouTube のリンクを載せられる(任意・初期は非公開。2026-09-26)。同居人との共有は有料プラン(カップル・夫婦・家族などで記録を共有して、一緒に管理できる) |
| 売買・交換 | 売る出品には、出品者の公開している記録が必要(2026-09-26。同日午前の「誰でも出品できる」を改めた)。最低ラインは写真のみの公開で、何か公開している記録が1件以上あればよい。判定はアカウントごと(記録する植物と、売買・交換する物は、対応させなくてよい)。株ごとに非公開にでき、非公開の株は数えない。譲る・交換の出品と、買う人・交換に応じる人は、記録の公開は任意。資材の出品は記録の公開が不要。記録は信頼を上げる表示でもある(相手の育て方を見られる)。対象は植物と資材。同時出品数は無料枠あり(有料で拡大。ステップ5)。交換は無料枠(制限しない)。弱った株・不要な株は「レスキュー株」区分 |
| 取引の方式 | 固定価格と交換のみ。入札(オークション)形式にはしない。代金は自分で預からず、決済代行サービスを使う |
| コミュニティ | 入荷の共有(ユーザーが買ったとき「ここに○○があった」と共有する機能。運営は入荷情報を扱わない。2026-09-26)、相談Q&A(病気や困りごとを投稿して、相互にコミュニケーションできる場。知恵袋の観葉植物版。**すべて無料**。AI の一次回答は1日の回数に上限をつけて無料。**ステップ6から前倒し**(時期はステップ2を案)。ポイントをイベントで使える仕組みは保留=しばらく先。2026-09-26)、イベント(関東・関西から→全国、会場での交流・交換、周辺店舗への送客) |
| イベント情報の提供 | 当初は無料。**ステップ2の核はイベント情報**。生成AIで収集し、確度の高い情報だけを載せる(出典リンクと確認日つき)。店・主催者への有料掲載は、関心を確認してから(後回し)。**入荷情報は運営としては扱わない**(掲載も AI 収集もしない)。入荷は、ユーザー同士の共有機能(買ったとき「ここに○○があった」と共有)。入荷通知は無料の範囲(2026-09-26) |
| 通知 | 全種類あわせて原則1日1回まで。通知の許可は最初の撮影のあとに求める。撮影通知・水やり通知はどちらも初期オフで、希望した人だけオンにする(2026-09-26。聞き取りで「定期通知は面倒」という声) |
| 盗難対策 | 公開する地域は都道府県まで。株の価格・コレクションの規模は初期設定で非公開 |

### 開発の順番
- 来歴記録(ステップ1)→ イベント・相談Q&A・有料プランの開始、6か月目ごろにストア公開(ステップ2。相談Q&Aは2026-09-26 にステップ6から前倒し。有料プランの開始はステップ4から前倒し。入荷情報は運営では扱わない)→ 記録を見せ合う(ステップ3)→ 有料プラン(ステップ4)→ 売買・交換(ステップ5)→ 拡大(ステップ6)。その前にステップ0(準備)。
- 「相手の記録を見られる機能」を売買より先に作る。
- 当面(2026-09-26 決定)は、ステップ1の生育記録(機能)の作りこみを優先する。見た目は作り込まず、ワイヤーフレーム方針(`docs/dev-rules.md` 3章)のまま、全画面の機能を先につなぐ。店・主催者への確認、競合との比較は後回し。SNS の投稿量の調査は保留。

## 2. 未決事項
### 2026-09-26(売買の条件・有料プランの見直し)に出たもの
- **記録の共有の詳細**:招待される側は無料にする案(共有される人も利用者になる)。共有できる人数の上限を決める。
- **無料の同時出品数**:何件までにするか(ステップ5の設計で決める。交換は無料枠で、制限しない)。
- **(決定済み・2026-09-26)コレクション画面・台帳の方向**:1枚絵は、A 写真ポスターとB 置き場所マップから始める(Bから水やり・健康状態を操作)。共有用の書き出しは、透かし付きが無料、透かしなしが有料。共有用に出す項目(名前・株の数・置き場所・価格)は選べて、初期は出さない。台帳は、入力と株ごとの表示が無料、集計と書き出しが有料。購入価格は、ステップ1で任意項目に入れる。時期は、ステップ1の後。
- **(決定済み・2026-09-26)健康状態と履歴**:健康状態(初期・元気・要観察・不調・復活中)をステップ1に入れる。変えるたびに記録として残り、株ごとの履歴でたどれる。コレクション全体の履歴は後。未決:公開の範囲に含めるか(要件 Q12)、「初期」の名前(Q13)。
- **鉢ごとの費用のまとめ(将来構想)**:鉢ごとの費用(鉢・肥料など)を集計する。土などは共用として、鉢には割り当てない。有料プランの候補。設計は着手前に決める。
- **SNS への投稿の簡略化(構想・2026-09-26)**:成長記録を、各 SNS のテンプレートつきで簡単に投稿できるようにする。共有リンクから、ログイン中のアカウントの投稿画面へ、文面・画像・リンクを埋めた状態で移る(アプリは SNS の認証情報を扱わない)。未決:対象の SNS、テンプレートの内容、時期(画像の共有はステップ1の後、公開リンクつきはステップ3以降を案)。各 SNS の投稿画面の仕様(文面を埋められるか)は、作る前に確認する。
- **(決定済み・2026-09-26)有料プラン**:月480円/年額4,800円。ステップ2のストア公開から開始。中身は「記録の共有」「登録数の上限なし(無料は現役の株15まで)」「広告非表示」、ステップ5から「出品の拡張(同時出品数の拡大・出品オプション込み。交換は無料枠)」。高画質・入荷通知の拡大は有料にしない。残りの未決:記録の共有の招待される側の扱いと人数、無料の同時出品数、コレクション台帳と1枚絵(有料の候補)。
- **画質の区別**:高画質を有料の特典から外したため、無料(長辺1600px)と有料(3000px)の区別を続けるか、全員同じにするかを決める。全員同じにする場合は、`docs/spec/requirements.md` の REQ-020 とサーバー処理(`functions/src/index.ts` とそのテスト)を変える。
- **(決定済み・2026-09-26)無料の登録数の上限**:現役の株15まで(手放した株・枯れた株は数えない)。テスターで確かめて調整する。素材のダウンロードと出品は、上限の影響を受けない。
- **(決定済み・2026-09-26)入荷情報**:運営としては扱わない(掲載も AI 収集もしない)。入荷は、ユーザーが買ったときに「ここに○○があった」と共有する機能。ステップ2の核はイベント情報。入荷通知は、共有への通知として無料の範囲。**未決:共有機能を作る時期(ステップ2〜3)と設計**(投稿者の位置・店への迷惑・誤情報・ステマ・写真)。
- **出品と記録の見せ方**:出品ページから、出品者の公開している記録を見られるようにする。出品と記録の株の、任意のひもづけをするか。「来歴つき」の表示の出し方。
- **出品オプションの中身**:上位表示を「来歴つき」だけにする案は、売る出品の条件が「記録の公開」(来歴つきとは限らない)になったため、見直す。
- **詐欺・転売への対策**:譲る・交換は記録なしでも出せ、売る出品も写真のみの公開で足りるため、評価・通報・年齢確認(売買は18歳以上)などの対策を、ステップ5の設計で決める。
- **売る出品の記録公開の詳細(方針は2026-09-26に決定。以下は未決)**:①記録の公開を止めたとき、出品中の「売る」出品をどうするか(自動で取り下げる/期限まで残す など)。②「何か公開している記録」に、相談の投稿・回答を含めるか(相談はステップ2)。③条件はサーバー側で判定する(画面で隠すだけにしない。ステップ5の設計)。④ステップ1のテスターに「売る出品に記録の公開が必須なら出すか」を聞いて確かめる。
- **判定点の読み替え**:記録の公開率は、売る出品の条件を満たす人が十分いるか、公開のハードルが高すぎないかの指標になる(`evaluation.md` 11か月目)。

### 2026-09-26(対象・Q&A・収益の見直し)に出たもの
- **市場規模の再計算**:対象が「ハマっている層」から「初心者から少し踏み込んだ層以上」に広がったため、TAM/SAM/SOM と5年の収益見通し(`market-and-revenue.md`)を作り直す。あわせて、売買手数料は、アプリ外で成立する分を除いたアプリ内成立分だけで見積もる。
- **ポイント制度(保留。しばらく先の機能。2026-09-26)**:ベストアンサー率が高い人にポイントを付与し、イベントで使えるようにする案。実施を決めるときに、ポイントの付け方・使える場面・費用の出どころ、法令の確認(ポイントを購入できるようにすると資金決済法の前払式支払手段、景品にあたる場合は景品表示法など)、不正(自作自演のベストアンサー・複数アカウント)への対策を決める。`security-requirements.md` にも追加する。
- **(決定済み・2026-09-26)相談Q&Aの前倒し**:ステップ6から前倒しする。時期は、ステップ2(入荷情報・イベントと同じ、ストア公開のとき)を案とする。前倒しは決定、時期は案。
- **(決定済み・2026-09-26)AI の一次回答**:1日の回数に上限をつけて、無料にする(有料プランでの緩和はしない)。上限の回数と、費用の見込みは、ステップ2の設計で決める。
- **(確認済み・2026-09-26)「コメント記録」**:記録につけるコメント(メモ)。ステップ1は既存のメモ機能(REQ-023)で足りる。他の人からのコメントは、ステップ3以降。
- **ステップ2の作業量と削る順**:ステップ2に、イベント・相談Q&A(AI 一次回答つき)・有料プランの開始(課金の仕組み)・広告・ストア公開が入り、作業量が大きい。削る順(例:広告を後回し → イベント通知 → 相談Q&A の順に優先)を、ステップ2の設計で決める。
- **相談Q&Aの設計**:質問・回答の公開範囲、記録の添付、AI への送信範囲と同意、危険な回答(農薬・有毒植物)への対応、通報と削除を、ステップ2の設計で決める。`security-requirements.md` のフェーズ対応(相談=2a+)を、ステップ2に直す。

### 2026-09-26 に出たもの
- **判定点の指標**:8か月目の判定点「入荷情報の投稿が関東・関西で週10件以上」(`evaluation.md` 5章)は、運営が入荷情報を扱わなくなったため、読み替える(例:イベントの掲載件数と誤りの報告の割合、共有の投稿数、有料会員数)。有料プランの開始がステップ2に前倒しされたため、8か月目に有料会員の数(最初の目標:10人)も見る。
- **AI 収集の仕組み(イベント情報だけが対象)**:元にする情報源の範囲、確度の判定方法、費用の上限、間違いがあったときの訂正の流れ。ステップ2の設計で決める。
- **リンクの許可ドメイン**:載せられるサービスの一覧(Instagram・X・YouTube など)。ステップ3の設計で決める。
- **引用時の画像の印**:公開した記録を他の SNS で引用するとき、画像に株のページへたどれるリンクや QR を付けるか(写真の使い回しへの対策)。ステップ3以降で検討。
- **聞き取りで確認できていないこと**:手持ち株に来歴が付かないことへの受け止め、盗難への不安、「取引のためなら公開する」人の割合、来歴つきの株に買い手が高く払うか、入荷通知に月480円払うか、親株の持ち主による確認(親子リンク)への反応。

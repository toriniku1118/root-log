# 植物アプリ コンセプト(2026-09-25 時点・ドラフト/対象を「ハマっている層」に変更)

## 方針(ユーザー決定)
- **このサービスの根底は「交流と交換」**(2026-09-26)。ハマっている人どうしが、記録を見せ合い、イベントや取引で株・資材を交換し、交流する。成長記録・来歴は、交流と交換を効果的に実現するための記録で(相手を知る手がかり・話のきっかけ・信頼)、記録そのものが目的ではない。以降の機能・順序・文言は、交流・交換を効果的にしているかで判断する。
- **作り込む中核は3本**(2026-09-26):「記録」「交換・売買」「交流」。記録も重要だが、作りはシンプルでよい。記録機能を作り込みすぎず、手間は交換・売買と交流を効果的にする部分にかける。ゴースト表示・巡回モード・タイムラプスは後回しにし、代わりに自分の写真(素材)をすべてダウンロードできるようにする(タイムラプスなどは自分で作れる)。
- セキュリティ要件を最重要とする。機能の追加・納期よりも優先し、プロトタイプ(ステップ1)から満たす。詳細は「植物アプリ_セキュリティ要件」。
- 対象(2026-09-26 更新):観葉植物を育てている、初心者から少し踏み込んだ層以上。年齢層は特定しない。株がどんどん増え、使わない資材・欲しい資材・売りたい植物がある人が、他の育てている人の背景(記録)を見ながら売買・交換できるサービスを目指す。病気や困りごとを投稿して、相互にコミュニケーションできる場にもする。はじめは記録アプリから始める(水やり・鉢替え・その他の記録・コメントなど、一般的なところから)。以下の「ハマっている層」は、その中心となる人たち(2026-09-25 変更。以前は「始めたばかりの若手」)。塊根植物・アガベ・ビカクシダ・珍奇植物・アロイド・実生などに熱中し、株を集め、店やイベントを回り、SNSで発信・交流している人。詳細は下記「対象ユーザー」「ハマっている層のコミュニティの現状」。
- PlantaやGreenSnapとは「AIの世話支援・写真SNS」で競わない。
- アプリの柱:
  1. 成長記録:植物のリスト管理、タイムラプス的な写真管理、栽培ストーリー、その他の標準的な記録。水やりは「水をやった」ボタンで1タップ登録するのが基本。定期通知(撮影・水やり)は初期設定オフで、本人が希望した場合だけ知らせる(オプトイン。水やり通知は、その人の記録から出した「いつもの間隔」で知らせる。2026-09-25 変更、2026-09-26 に撮影通知も初期オフへ)。育てている植物の好みのジャンル分け、植物の提案。同居人との記録共有は有料プランの機能(カップル・夫婦・家族などで一緒に管理でき、楽しみが増える)。
  2. 売買:一般的な売買+交換で構成。相手の成長記録を見られることで差別化。売買・交換は、成長記録を公開しているユーザーだけが使える仕様。
  3. イベント:まず関東・関西、将来は全国。イベントの場をユーザー同士の交流の場にし、植物や資材を交換。あわせて周辺の店舗へ送客・販促。
  4. 相談Q&A:Yahoo!知恵袋の観葉植物版として提供(設計・評価は下記⑤)。病気や困りごとを投稿して、相互にコミュニケーションできる場。**すべて無料**。将来は、ベストアンサー率が高い人にポイントを付与し、イベントで使えるようにする仕組みを検討する(2026-09-26。法令確認と不正対策が要る。`decisions.md` の未決事項)。
  5. コミュニティ内でのレア植物の販売場所の共有(設計・評価は下記⑥)。
  6. レスキュー株:弱った株・不要な株を安く(または無償で)譲り、引き取った人が復活させる。売買・交換の一区分+記録の「復活チャレンジ」(設計・評価は下記⑦)。
- 栽培記録を共有するかどうかは、ユーザーが選べる(公開・非公開、相談への添付の有無など)。例外として、売買・交換を使うには記録の公開が必要。公開すると、売買・交換・レスキューでの信頼材料になり、他の SNS などで引用して見せられる(2026-09-26)。公開プロフィールには SNS・YouTube のリンクも載せられる(任意)。
- 資材もジモティー等の汎用サービスではなく、あえて植物専用にする(仮説:植物専用の方がマッチしやすい。物によっては発送もできる)。
- イベント情報・入荷情報は、当初は無料で提供する。収集は生成AIで行い、確度の高い情報だけを載せる(2026-09-26)。店・主催者への有料掲載は、関心を確認してから。
- 収益の柱は有料プラン(入荷通知等)と取引(手数料・出品オプション)。広告は補助(2026-09-25 決定。以前は「広告が第一」)。取引がアプリ外(現金の手渡し・他のサービス)で成立するのは仕方がない(メルカリなど他の売買サービスも同じ)。手数料はアプリ内で成立した分だけで見積もる(2026-09-26)。確定した開発の決め事は「植物アプリ_開発の決め事」を参照。
- 開発順:「相手の成長記録を見られる機能」(ステップ3)を先に作り、その後に売買・交換(ステップ5)。詳細は「開発ステップ」。
- 検証方法:LINEオープンチャット等の手作業の実験は行わない(仕組み化できないため)。アプリのプロトタイプを作り、個人で運用しながら課題を抽出する。
- いずれも仮説段階で、検証が必要。
- 参考機能の抽出は「植物アプリ_参考機能_趣味の園芸_Planta」、市場規模と収益見通しは「植物アプリ_市場規模と収益見通し_2026-09」を参照。

## 開く理由と通知設計(2026-09-25 追加)
### 考え方
- 広告と有料プランは「毎日開くか」で決まるため、開く理由を複数用意する。観葉植物は1日ではほとんど変わらないので、撮影を中心に「週単位」の習慣を基本にし、入荷情報・反応などで日々の理由を足す。
- 通知は多すぎると通知ごとオフにされるので、全体で上限と優先順位を決める。

### 7つの仕組み
| 仕組み | 開く頻度 | 効き方 | 時期 |
|---|---|---|---|
| ① 成長記録の撮影 | 週1〜 | 習慣の中心 | ステップ1 |
| ② 近くのイベント通知 | 月数回 | 外出・交流のきっかけ | ステップ2 |
| ③ 水やり通知(オプトイン) | 週数回 | 一番高頻度 | ステップ1 |
| ④ 季節・天気のお知らせ | 月1〜2 | 役に立つ・株を守る | ステップ2〜3 |
| ⑤ 反応の通知(いいね・コメント・回答) | 不定期 | 一番強い動機 | ステップ3 |
| ⑥ 入荷情報・欲しいもの通知 | 不定期 | 取り逃したくない | ステップ2(入荷情報)、ステップ4(入荷通知の拡大)、ステップ5(欲しいもの) |
| ⑦ 月のまとめ・テーマ | 月1 | 見返したい・SNS共有 | ステップ3 |

### ① 成長記録の撮影
- きっかけ:撮影通知は初期オフ(聞き取りで「定期通知は面倒」という声。2026-09-26)。オンにした人は、株ごとに頻度を選べる(週1が初期値、毎日も可)。複数の株をまとめて1日1回まで、時間は本人が決める(例:日曜の朝)。ホーム画面のウィジェット(「モンステラ、前回の撮影から8日」+最新写真)で、通知なしでも開く理由を作る。
- 手間を減らす:通知から直接カメラを起動。前回の写真を半透明で重ねるゴースト表示で毎回同じ角度に(タイムラプスの仕上がりを左右する差別化点)。巡回モード:置き場所の順に全株を続けて撮り、その流れで「水をやった」も1タップで記録。1回1〜2分で終わる。
- 撮った直後のごほうび:保存した瞬間に「1週間前・1ヶ月前」と並べて表示。タイムラプスがその場で1コマ伸びる。「新芽」「3ヶ月記録」などの節目を栽培ストーリーに自動で残す。
- 連続記録は週単位にし、途切れても責めない見せ方(毎日の連続記録は植物のペースに合わず、途切れた時の離脱原因になる)。
- 積み重ね:記録がたまるほど他のアプリに移りにくくなる(Plantaとの差)。

### ② 近くのイベント通知
- 基本は登録した地域(市区町村)をもとに通知。GPSは「使用中のみ」の任意とし、常時の位置情報は求めない(許可率が低く、プライバシーの不安が大きいため)。
- サーバーには座標を保存せず、地域コードだけを持つ(セキュリティ要件 5章)。
- 1週間前と前日に通知。「行く」でカレンダー登録、行く予定の人数を表示。
- イベント後に「買ったもの・撮った写真」の記録を促し、①の撮影につなげる。

### ③ 水やり通知(オプトイン)
- 初期設定はオフ。本人が希望した株だけ。
- 一般的なスケジュールではなく、その人の記録から出した「いつもの間隔」で知らせる(例:「前回から6日、いつもは5日おき」)。記録がたまるほど精度が上がるので、記録する動機にもなる。
- 通知から1タップで「やった」と記録。夏と冬の間隔の違いも記録から自然に反映。

### ④ 季節・天気のお知らせ
- 寒波・猛暑の前(「今夜5℃、窓際の株は室内へ」)、植え替えの適期など。回数は少ないが株を守れるので信頼が上がる。
- 天気は地域単位で取得すれば十分。天気データの利用規約・費用は要確認。

### ⑤ 反応の通知
- いいね・コメント・相談への回答。記録を公開する動機にもなり、ステップ3の核。
- 「自分が育てている品種の質問」を回答できそうな人に届け、相談の回答を集めやすくする。

### ⑥ 入荷情報・欲しいもの通知
- 好きな品種の入荷情報(上記⑥の機能)。「欲しい鉢・資材」を登録しておくと、近くで出品されたときに通知(売買・交換の「探しています」)。

### ⑦ 月のまとめ・テーマ
- 月初に「今月の成長ムービー」を自動で作って届ける(見返すために開く、SNS書き出しで集客)。あわせて季節のテーマ(例:「10月は紅葉する株」)を出す。

### 通知全体のルール
- 全種類を合わせて原則1日1回まで。重なった日は優先順位(反応 → 天気の警報 → 撮影・水やり → その他)で1つにまとめる。
- 種類ごとにオン/オフできる(初期値は適切に設定し、細かい設定は必要な人だけ)。
- 通知の許可は起動直後には求めず、最初の撮影のあとに「来週また撮る日を知らせますか?」と理由が伝わる場面で聞く。選ばなければ通知はオフのまま(オプトイン)。

### 収益とのつなげ方
- 撮影の流れの途中には広告を入れない。保存後の画面に「同じ品種の他の人の記録」「近くの入荷情報」を出して滞在を延ばし、そこで広告を表示する。

### 見る数字
- 週1回以上撮影したユーザーの割合、通知から開いた割合、1人あたりの撮影株数、通知許可率、通知をオフにした割合、種類ごとの開封率。→ 30日後の継続率(D30)15%以上につながるかを確認。

## 対象ユーザー(2026-09-25 変更)
- 変更理由:SNS調査で、収益につながる入荷情報・イベント・取引に熱心なのは「ハマっている層」であり、始めたばかりの層は「育てやすさ」重視で関心がずれていたため(「植物アプリ_SNSニーズ調査_2026-09」)。
- 主な対象:塊根植物・アガベ・ビカクシダ・珍奇植物・アロイド・実生(種から育てる)などに熱中している人。育成ライト・温室などに投資し、株に数千円〜数十万円を払い、店・イベントを回り、X・Instagram・YouTubeで発信・交流している。
- 扱うジャンルは観葉植物全般(パキラ・モンステラ・ポトス等)も含む(2026-09-25 決定)。ハマっている層も一般的な観葉植物を多く育てており、記録の対象を狭めないため。
- 始めたばかりの人も使えるが、機能の優先度・画面・言葉づかいはハマっている層に合わせる。
- 1つのジャンルのブームに依存しない(アガベは組織培養の普及で価格が大きく下落した)。複数ジャンルを横断して扱う。

### ハマっている層の困りごと(=本アプリの機会)
1. 取引の詐欺・偽物:幼い子株は品種の見分けがつかず、品種名の偽装や、親株の写真を使い回して別の株を売る手口がある。「本物かは育つまで分からない」。→ 株の来歴(親株・子株が付いた状態・発根・成長の経過)が記録として見えることが、そのまま信頼になる。「記録を公開している人だけが取引できる」仕様と直結する最大の機会。
2. 盗難:数万円のアガベや、時価100万円相当のパキプスの盗難が報道されている。→ 住んでいる場所・コレクションの価値が知られないことが必須(セキュリティ要件をさらに強める)。
3. 転売・盗掘株・ワシントン条約:趣味の持続性への懸念が愛好家の間にある。→ 実生・国内増殖株の記録を評価する文化を作る。
4. 情報の分散:入荷情報・イベント情報が店・主催者ごとのSNSに散らばり、流れて残らない。→ 品種・地域でまとまる入荷情報とイベント。
5. 議論の荒れ・疲れ:X上の批判・マウントの応酬。→ 記録を中心にした、落ち着いて見せ合える場。フォロワー数や価格を前面に出さない。

### 対象変更による設計の変更点
- 追加:株の来歴記録。親株の写真、子株が付いた状態、実生の播種日、発根・成長の経過を、アプリ内カメラで撮影した日時つきの記録として残す(後から撮影日時を変えられない形。端末内の写真の後付けは「来歴」とは区別して表示)。取引ページに来歴を自動で添付し、「来歴つき」「実生記録つき」を表示。
- 追加:実生(種から育てる)の記録。播種から発芽・成長までのタイムラプス。実生株の出品に来歴として使える。
- 強化:位置情報と盗難対策。公開プロフィールの地域は都道府県まで。株の価格・コレクションの規模を公開しない選択を初期設定に。取引での受け渡し場所は公共の場所を推奨。
- 強化:取引の安全。高額取引では、決済代行サービスによる代金の一時預かり(自前では預からない。資金決済法の確認)を検討。評価・通報・品種偽装の通報。
- 優先度を上げる:入荷情報、イベント、売買・交換。
- 優先度を下げる:同居人との共有(有料プランの特典の1つとして残す)、初心者向けの植物の提案、初回の質問の初心者向け項目。
- 収益への影響:取引の単価が数千円〜数万円になるため、売買手数料・出品オプションの比重が上がる。一方で対象人数は初心者より少ない → 市場規模(TAM/SAM/SOM)は再計算が必要。

## ポジショニング
- Planta:世話を教えてくれる「先生」(水やり計算・AI診断・照度計)。
- GreenSnap:植物写真のSNS+育て方情報+自社ストア(30〜40代女性が中心)。
- みんなの趣味の園芸:図鑑+栽培レポート+日記+Q&A(中高年が約7割、2013年時点)。
- 本アプリ:ハマっている人のための「株の来歴が見える」記録と取引の場+レア植物の入荷情報+中立なイベント情報と会場での交流+記録つきの相談。

## 記録の共有範囲
| 共有の種類 | 初期設定 | 選び方 | 備考 |
|---|---|---|---|
| 植物ごとの公開(他のユーザーが閲覧できる) | 非公開 | 植物ごとに公開/非公開を選ぶ | 公開時は写真の位置情報(EXIF)を自動削除 |
| 公開範囲の細かさ | — | 写真のみ/写真+水やり・植え替え履歴/入手先まで、を選べる | 入手先(店名・交換相手)は個人が特定されうるため別に選択 |
| 相談への添付 | 添付しない | 質問ごとに「この植物の記録を添付する」を選ぶ。添付する範囲(期間・写真)も選べる | 添付しなくても質問できる。添付すると回答が集まりやすい旨を案内 |
| 公開プロフィールのリンク(SNS・YouTube) | 非公開 | 本人が載せるかどうかを選ぶ | 個人の特定につながりうるため任意。載せられるのは決めたサービスだけ(https)。本人が申告したリンクで、本人確認済みとは表示しない(他人のアカウントを載せられるため) |
| 同居人との共有(有料) | — | 招待した相手とだけ共有 | 公開設定とは独立 |
| 売買・交換 | — | 利用するには、少なくとも1つの植物の記録を公開する必要がある | 出品する植物・自分で選んだ植物だけの公開でよい |
- 考え方:共有は本人が選べるのが基本(公開は任意)。ただし「記録を見せる」ことで得られる価値(回答が集まる、取引で信頼される、他の SNS で引用して見せられる)を分かりやすく示し、公開したくなる動機を作る。
- 公開しない人も記録・イベント・相談の閲覧・質問は使える(公開率が低くなりすぎないか、ステップ3で確認)。
- 公開範囲の制御はサーバー側で強制する(セキュリティ要件 4章)。

#### 「記録を公開していないと使えない」仕様の評価
- 良い点:①取引相手の信頼が上がる ②業者・転売目的・冷やかしの出品を抑えられる ③売買のために記録を続ける動機が生まれる ④メルカリ・ジモティーとの違いが明確になる。
- 懸念点:①出品のハードルが上がり取引数が減る ②記録を公開することへの抵抗 ③新規ユーザーはすぐに取引できない。
- 対策:①最低条件を低めに設定し調整 ②公開する植物・項目を本人が選べる、位置情報の自動削除、自宅が写る写真への注意喚起 ③記録の期間・件数をプロフィールに表示し、条件を満たすまでの道のりを見せる ④閲覧を誰でも可能にするかは要検討。

### ⑤ 相談Q&A(知恵袋の観葉植物版)
#### 需要の目安
- Yahoo!知恵袋の「観葉植物」カテゴリには、1日あたり約10〜15件の質問が投稿されている(回答受付中の一覧に表示された投稿日時から推定、2026年9月23〜25日)。内容は「根腐れしているか」「葉が枯れる」「水やり・日当たり・植え替え時期」「この植物は何か」「剪定・徒長」など。

#### 既存の選択肢
- Yahoo!知恵袋(汎用、利用者が多い、無料)、みんなの趣味の園芸 園芸相談Q&A(2020年〜、「役に立った!」ボタン、講師回答の企画)、GreenSnap(AI相談・コミュニティ)、生成AI(ChatGPT等)。

#### 差別化:「記録つきの相談」(添付は任意)
- 質問に自分の栽培ストーリー(水やり履歴・置き場所・植え替え日・写真の変化)を、選んだ範囲だけワンタップで添付できる。添付しなくても質問できる。知恵袋で聞き返されがちな情報が最初からそろい、回答の質と速さが上がる。
- 回答者が記録を公開していれば、その栽培ストーリーも見える → 「本当に育てている人の回答」か判断できる。記録公開者には目印(バッジ)を表示。
- 質問した株のその後が栽培ストーリーに残る → 「その回答で結果どうなったか」が分かる(知恵袋にない)。

#### 回答が集まらない問題(立ち上げ)への対策
- 当初は、生成AIがまず一次回答(添付された記録があればそれをもとに)し、人の回答を待つ形。AIの回答には「参考情報」と明示。AIへの送信範囲はセキュリティ要件 8章に従う。
- 自分(開発者)も初期の回答者として参加。
- 回答の実績(ベストアンサー数・役に立った数)をプロフィールに表示し、売買・交換での信頼にも反映 → 回答する動機を作る。

#### 集客・収益への効果
- 質問ページを(本人の許可のうえで)Web上にも公開すれば、「パキラ 葉が黄色い」などの検索から人が来る入口になる(アプリ内だけでは検索に出ない。Web版の質問ページが別途必要)。
- 質問ページは閲覧数が多く、広告の表示機会になる。回答内の資材・薬剤の紹介は送客にもなりうる(中立性に注意)。

#### 懸念点と対策
- 回答が集まらない:上記の立ち上げ対策。質問数が少ないうちは品種ページや記録閲覧と一体で見せる。
- 誤った回答で植物が枯れる・トラブル:回答は参考情報である旨を明記、ベストアンサー・役に立ったで良い回答を上に表示。
- 危険な内容:農薬・薬剤の誤った使い方、ペットや子どもに有毒な植物の扱いは、注意書きと通報・削除の方針を用意。
- 運営の手間:通報・禁止ワード・自動検知を最初から。回答者は制限しないが、記録公開者にはバッジを表示して区別。荒れる場合は回答条件の追加を検討。
- AI回答の費用:1回ごとにAPI費用がかかる → 1日あたりの回数上限、有料プランで上限を緩和。
- 生成AIとの競合:汎用AIは「記録」と「実際に育てている人の経験」を持たない点で差をつける。

### ⑥ レア植物の販売場所の共有(入荷情報)(2026-09-25 追加)
#### 狙い
- レア植物を探している人は、店の入荷情報をこまめに確認する → 毎日開く理由になり、広告の表示回数(=第一の収益源)を直接押し上げる。
- 店舗にとっては「その植物を探している人」に直接届く告知の場になる → 法人向けの有料掲載につながる。
- 記録(「入手先」)・品種ページ・探しています・イベントと自然につながる。

#### 機能案
| 機能 | 内容 | 段階 |
|---|---|---|
| 生成AIによる収集 | 店・主催者の公式サイトなど、公開されているページから、確度の高い情報だけを集めて掲載(無料)。出典リンクと確認日をつける。SNS の自動収集はしない(規約) | ステップ2〜 |
| ユーザーの入荷情報投稿 | 「どの店で・何の品種を・いつ見たか・価格帯・在庫の目安・写真」を投稿。AI収集と併用するかは未決(`decisions.md` の未決事項) | 未定 |
| 情報の鮮度・訂正 | 確認日の表示、「違っていた」「まだあった/売り切れ」の報告、一定期間で自動的に古い表示 | 同上 |
| 品種・地域で探す | 品種ページ・地域(関東・関西)・ジャンルで入荷情報を一覧 | 同上 |
| 入荷通知 | 探している品種・好きなジャンルの入荷情報が投稿されたら通知。無料は件数・品種数に上限、有料プランで拡大・即時通知 | ステップ2(基本)、ステップ4(有料で拡大) |
| 店舗の公式アカウント | 店舗が入荷情報を直接投稿。無料で開始し、上位表示・通知枠・店舗ページの充実を有料化 | ステップ6〜 |
| 記録との連動 | 入荷情報から買った株を登録すると、入手先・日付が自動で記録に入る | ステップ2〜 |

#### 懸念点と対策
- 法令・規制:ワシントン条約(CITES)の対象となる一部の植物(塊根植物・サボテン等の一部)の違法な輸入株、自生地からの盗掘株、特定外来生物を扱う店の情報は掲載しない方針を規約に明記し、通報で削除。
- ステルスマーケティング規制(景品表示法の告示、2023年10月施行):店舗から対価を受けた掲載・上位表示は「広告」「PR」と明示する。ユーザー投稿を装った店舗の宣伝は禁止。
- 情報の正確さ:古い・誤った情報で無駄足になる。生成AIは日付・場所を誤ることがある → 確度の高い情報だけを載せる、出典リンクと確認日の表示、「違っていた」報告、一定期間で自動的に古い表示。入荷情報は在庫が日々変わるため、AI収集だけでは鮮度を保ちにくい(イベントを先に、入荷はゆるい情報として扱う)。
- 店舗の迷惑:店内撮影を禁止している店がある、問い合わせの殺到 → 撮影ルールを守る注意喚起、店舗から掲載停止を依頼できる窓口。
- 転売目的の買い占め:通知が転売に使われる懸念 → 取引機能では記録公開を条件にしており、転売目的の出品を抑える仕組みと併せて運用。入荷通知の即時性を有料の特典にしすぎない配慮も検討。
- プライバシー:投稿者の「今いる場所」が分からないよう、投稿時刻をぼかす・遅らせて公開する選択肢。店舗の情報は共有するが、投稿者本人の位置は共有しない(セキュリティ要件 5章)。
- ブームの変動:アガベのように組織培養の普及で価格が暴落する例もある → 特定のジャンルに依存しない(観葉・多肉・塊根・ビカクシダ等を広く扱う)。

### ⑦ レスキュー株(弱った株・不要な株を安く譲り、復活させる)(2026-09-25 追加)
#### 狙い
- 病気・害虫・根腐れ・徒長・未発根などで弱った株や、手放したい株を、安く(または無償で)譲り、引き取った人が復活させる。
- 復活の過程は栽培ストーリー・タイムラプスの最も見応えのある素材になり、SNSでの共有・集客につながる。
- 安く引き取って復活させた株を来歴つきで出品できる → 「育てて価値を上げる」流れ。復活の実績は育成の腕の証明になり、取引での信頼が上がる。
- 見切り品の復活や未発根株の発根管理は、ハマっている層の中でもともと人気の楽しみ方。手放す側の「捨てにくい」罪悪感も減らせる。
- 名称は「リサイクル」ではなく「レスキュー株」(弱った株を救う意味が伝わるため)。

#### 機能案
| 機能 | 内容 | 段階 |
|---|---|---|
| 復活チャレンジのタグ | 栽培ストーリーに「復活チャレンジ」のタグ。見切り品や自分の弱った株の復活記録(ビフォーアフター)。月替わりテーマにも使う | ステップ1〜3(売買なしで開始) |
| 復活成功の表示 | 復活チャレンジを完了した株・ユーザーに表示(プロフィールの実績) | ステップ3〜 |
| レスキュー株の出品区分 | 売買・交換・無償譲渡の中に「レスキュー株」区分を追加。出品オプションなしの無料出品を基本 | ステップ5 |
| 症状の申告(必須) | 症状(根腐れ・害虫・病気の疑い・葉焼け・徒長・未発根 等)の選択、症状がわかる写真、害虫の有無、薬剤処理の有無 | ステップ5 |
| 購入者への案内 | 届いた株を他の株から一定期間離して管理する方法(隔離)を、購入時・到着時に案内 | ステップ5 |
| 元の持ち主への経過共有 | 引き取った人が、元の持ち主に復活の経過を見せられる(任意) | ステップ5 |

#### 懸念点と対策
- 病気・害虫を広げる(最大の懸念):ハマっている人は多数の株を持つため、1鉢で被害が広がりうる。→ 症状の申告と写真を必須、隔離の案内、治る見込みがなく他の株に移る病気(ウイルス病の疑い等)は出品禁止、申告と実物が違う場合の評価・通報を通常より重く扱う。
- 植物防疫:一部地域への発送制限がある害虫・植物は発送不可の案内。
- 低価格のため手数料収入は小さい:収益は出品・取引の数、毎日開く理由(復活の経過)、SNS共有による集客を通じて、広告・有料プランを支える役割。

### 作らない・後回しにする機能
- 一般的なスケジュールによる世話のリマインダー、AI診断、水やり計算(Planta・GreenSnapの得意領域)。※水やり通知は本人の記録にもとづく任意機能としてのみ提供。※相談のAI一次回答は「質問への補助」であり、世話の支援機能としては出さない。
- 本格的な植物図鑑(品種ページの軽量版で代替)。
- 写真での植物判定・照度の簡易測定(後回し。照度はカメラ画像からの推定を将来検討)。

### 反面教師(参考サービスの不満点から)
- 機能が多すぎて初心者が迷う(趣味の園芸)→ ホームは植物リストと記録ボタン中心、機能は段階的に表示。
- 通知設定が細かく面倒(趣味の園芸)→ 通知は種類を絞り、初期値を適切に。共有設定も「植物ごとにオン/オフ」を基本にし、細かい設定は必要な人だけ。
- 作業時期が関東基準(趣味の園芸)→ 地域を最初に設定し反映。
- サブスク・無料体験への強い誘導(Planta:ストア評価4.7に対しレビュー平均3.3)→ 基本無料、課金は任意で分かりやすく。
- AI判定の精度への不満(Planta)→ AI機能は中心にしない。

### 差別化の要素(強さ順)
1. 強:売買・交換が「記録を公開している人同士」に限られ、相手の栽培ストーリーと株の来歴(親株・子株・発根・実生の経過)を見て取引できること。ハマっている層の最大の困りごと(品種の偽装・写真の使い回し)への直接の答え。
2. 強:記録と交換の連動(植え替え→譲る/探す)。
3. 強:GreenSnapは自社ストアで新品を売るため、中古・余りを回す機能や他店の入荷情報は自社の売上と食い合い、追加しにくい可能性(推測)。
4. 中:中立な入荷情報(品種ごとの通知)。
5. 中:記録つきの相談Q&A(質問者・回答者の栽培ストーリーが見える、相談後の経過が残る)。
6. 中:中立なイベント情報+会場での交流・交換+周辺店舗への送客。
7. 中:ハマっている層向けの軽さ、共有範囲を本人が選べる安心感とセキュリティ重視、日本の号数規格・配送・法令の案内。
8. 弱:成長記録・写真管理そのもの(他社にもある。毎日開く習慣と交換のきっかけ役)。
- 競わない領域:名前判定、AI診断、育て方の知識、写真SNSの投稿量、水やり計算。

## リスクと対策
- セキュリティ・プライバシー(最重要):「植物アプリ_セキュリティ要件」に沿って、ステップごとの必須項目を満たしてから次に進む。
- 立ち上げ(地域の密度):関東・関西のイベントを起点に、会場周辺での受け渡しで密度を補う。発送できる物は全国対応。
- 公開が任意のため、公開される記録が少なくなりすぎる:公開の利点(相談の回答が集まる・取引で信頼される・品種ページに載る)を見せる。公開の案内を適切なタイミング(記録が一定数たまった時、相談する時)で出す。ステップ3で公開率を確認。
- 記録公開を取引の条件にすることで取引数が減る:最低条件を低めに設定し調整。
- イベント主催者との関係:即売会の会場で個人間の交換・売買をすると、出店者の売上と競合し主催者が嫌がる可能性。→ 会場内ではなく「会場周辺・前後」での受け渡しを基本にする。主催者と組む場合は交換ブースの公式設置など、主催者にもメリットがある形で相談。
- 見知らぬ人と会う安全面:人の多い公共の場所・時間を推奨、評価、未成年の扱い、トラブル時の対応方針を規約に明記。
- 周辺店舗への送客:店舗との個別の話し合い・契約が必要で手間がかかる。最初は店舗情報の掲載(無料)から始め、効果が見えてから有料化。
- 入荷情報:上記⑥の懸念点と対策(違法株・ステマ規制・情報の鮮度・店舗の迷惑・転売・投稿者の位置)。
- 機能の増えすぎ:週3〜7時間では全部同時に作れない。段階的に作る(下記MVP)。相談Q&Aは運営負荷が特に大きい。
- 開く理由が弱い・通知が多すぎてオフにされる:「開く理由と通知設計」の7つの仕組みで開く理由を作り、通知は原則1日1回まで・種類ごとにオン/オフ・許可は最初の撮影後に求める。
- 個人運用だけでは見えない課題:自分1人の利用では、他人の記録を見る・取引する・相談に答えるといった複数人前提の機能の課題が出にくい。→ 少人数の外部テスター(知人・イベントで知り合った人)を早めに入れる。
- GreenSnapが交換機能を追加するリスク:ハマっている層・株の来歴・号数規格・記録公開が前提の取引・中立なイベントと入荷情報・会場での交流に特化して先行。
- 新品の鉢が安い:交換の価値が大きいのは陶器鉢・デザイン鉢・大型鉢など。※未検証。
- 法務(要専門家確認):代金を預かる場合の資金決済法、特定商取引法の表示、利用規約、個人情報保護法(公開記録・写真)、景品表示法(ステマ規制)、ワシントン条約・種の保存法等に関わる植物の扱い。特定外来生物に指定された植物は譲渡禁止。一部地域への植物の持ち出しは植物防疫上の制限の可能性。イベント情報の転載は著作権・各サイト規約に注意。相談での農薬・薬剤に関する回答の扱い。

- 技術(案):Flutter または React Native+Firebase(写真の保存にはBlazeプラン〈従量課金〉の登録が必要。無料で使える範囲あり)。Apple Developer Program 年$99。Web公開にはWeb版(例:Next.js)が別途必要。公開範囲の制御はサーバー側の権限ルールで確実に行う。

### 各ステップで確認すること(次へ進む判断材料)
- ステップ1:自分とテスターが記録・撮影を続けるか。来歴記録を「取引で見せたい」と思うか。
- ステップ2:ダウンロード数、30日後の継続率、入荷情報の掲載数(関東・関西で週10件以上。生成AI収集での読み替えは未決)・閲覧数・正確さ(誤り・売り切れ報告の割合)、入荷情報を見るために開いた回数。
- ステップ3:記録の公開率(3割以上)、他の人の記録の閲覧数、公開ユーザーのうち売買・交換の利用条件を満たす人の数、「この人と取引したい」という声。
- ステップ4:有料プランの加入率(目安4%)、入荷通知の利用数。
- ステップ5:出品数・成立率、詐欺・トラブルの通報率、来歴つき出品の割合と成立率の差。レスキュー株の出品数・成立率、病気・害虫の持ち込みに関する通報の件数、復活して再出品された株の数。
- 全ステップ:非公開の情報が見えてしまう不具合・通報が0件であること。

## プロトタイプでの検証(個人運用で課題を抽出)
- 方針:手作業の実験(LINEオープンチャット等)は行わず、アプリのプロトタイプを作って自分で運用し、課題を抽出する。
- 自分で使うときに毎回残すこと:使いにくかった操作・かかった手間(例:水やり記録に何秒かかったか)・「欲しい」と思った機能・使わなかった機能。週1回まとめて振り返り、課題リストに整理。
- 自分で測る数字:毎日開いたか、記録の件数、写真の枚数、置き場所ごとのまとめ記録の利用回数、1回の撮影(巡回)にかかった時間、通知から開いた回数。
- 自分1人では見えない課題への対策:ステップ1の段階で、知人やイベントで知り合ったハマっている人数人をテスター(TestFlight等)として招待し、同じ項目を記録してもらう。公開・閲覧・取引・相談・入荷情報など複数人前提の機能は、テスターがいないと検証できない。テスターを入れる前にセキュリティのフェーズ1必須項目(ステップ1に対応)を満たす。
- イベント・店舗:関東・関西の植物イベントや植物店に実際に行き、来場者の層(ハマっている層の年齢・ジャンル)、取引の詐欺・偽物への不安、会場周辺で交換したいニーズ、周辺店舗、主催者の反応、店舗が入荷情報の掲載に関心を持つかを確認。アプリのイベント情報の登録作業にかかる手間も測る。
- テスター・イベントで聞くこと:「鉢や土が余った/足りなかった経験」「交換したいか」「相手の栽培ストーリーが見えたら安心か」「自分の記録をどこまでなら公開してよいか(写真のみ/履歴まで/入手先まで)」「取引のために記録を公開してもよいか」「植物イベントに行くか」「早く手放すために100〜300円払うか」「Planta・GreenSnapを使っているか、不満は何か」「水やりの通知は欲しいか、記録だけで十分か(いつもの間隔で知らせる形なら使うか)」「週1回の撮影通知があれば撮るか」「同居人と記録を共有したいか、そのために月300円程度払うか」「植物の悩みを普段どこで相談しているか(知恵袋・SNS・AI等)」「レア植物の入荷情報を普段どう探しているか(店のSNS・X・Instagram等)、通知があれば使うか」。

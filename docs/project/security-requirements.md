# 植物アプリ セキュリティ要件(最重要)(2026-09-25 ドラフト、2026-09-26 更新)

位置づけ:本アプリの要件の中で最優先。機能の追加・納期よりもセキュリティ要件を優先する。プロトタイプ(フェーズ1)の段階から満たす。
理由:本アプリは「栽培記録を本人が選んで公開する」「知らない人同士で取引・受け渡しをする」「同居人と共有する」ことが中心で、公開範囲の漏れや個人の特定は、そのままサービスの信頼の喪失につながるため。
※法令・ストア規約に関する記述は、実装前に最新版を確認し、必要に応じて専門家に相談する。

## 1. 基本原則
1. 初期設定は非公開(デフォルト拒否)。本人が明示的に選んだものだけを公開する。
2. アクセス制御はサーバー側(データベースの権限ルール)で強制する。アプリの画面で隠すだけの制御はしない。
3. 集める情報は最小限。使わない個人情報は取らない・保存しない。
4. 公開用のデータと非公開のデータは、保存場所から分ける。
5. 仕様の変更時は、必ず「誰が・何を・見られるか」を確認してから公開する。

## 2. 扱うデータと公開範囲
| データ | 例 | 既定 | 誰が見られるか |
|---|---|---|---|
| アカウント情報 | メールアドレス、ログイン情報 | 非公開 | 本人のみ(運営も必要最小限) |
| プロフィール | ユーザー名、好みのジャンル、地域(都道府県レベルまで) | 公開範囲を本人が選択 | 選択に応じて |
| プロフィールのリンク | SNS・YouTube のリンク | 非公開(載せるかどうかを本人が選択) | 本人が載せた場合のみ、ログインしている人 |
| 植物・記録 | 植物リスト、水やり・植え替え履歴、メモ | 非公開 | 本人、共有した同居人、本人が公開を選んだ場合は他のユーザー |
| 写真 | 植物の写真 | 非公開 | 同上。公開時は位置情報(EXIF)を削除した画像のみ |
| 入手先 | 店名・イベント名・交換相手 | 非公開 | 本人が別途選んだ場合のみ公開 |
| 置き場所 | 窓辺・ベランダ等 | 非公開 | 本人・同居人。公開時は名前のみ(住所等は持たない) |
| 取引情報 | 出品、取引の連絡、評価 | 取引当事者のみ(出品自体は公開) | 当事者・運営(通報対応時) |
| 相談 | 質問・回答・添付した記録 | 質問・回答は公開。添付は本人が選んだ範囲のみ | 選択に応じて |
| イベント参加情報 | 「行きたい」登録 | 非公開 | 本人が「同じイベントに行く人に表示」を許可した場合のみ |
| 位置情報 | 端末の現在地 | 取得しない(必要な場合も保存しない) | — |

## 3. 認証・アカウント
- 認証は実績のある仕組み(例:Firebase Authentication)を使い、パスワードを自前で保存しない。
- ログイン方法:メール+Apple/Googleでのログイン等。iOSで外部サービスのログインを提供する場合、Appleの審査ガイドラインが求めるプライバシーに配慮したログイン手段(Sign in with Apple等)の提供要否を確認。
- アプリ内からアカウント削除ができること(App Storeの審査要件)。削除時は記録・写真・公開データも削除(取引の記録など法令上保存が必要なものは保存期間と扱いを規約で明示)。
- 同居人共有の招待は、招待リンクの有効期限・1回限り・いつでも解除できる仕組みにする。

## 4. アクセス制御(最重要)
- データベース・写真保存先の権限ルールは「すべて拒否」から始め、必要な読み書きだけを許可する。
- データベースの権限は文書(ドキュメント)単位で決まることが多いため、非公開の項目と公開の項目を同じ文書に混ぜない。公開用のデータは、サーバー側の処理で「公開を選んだ項目だけ」を別の場所に書き出す。
- 植物ごと・項目ごと(写真のみ/履歴/入手先)の公開設定を、権限ルールまたは公開用データの書き出し処理で確実に反映する。
- 公開を取り消したら、公開用データ・Web公開ページ・検索用の索引からも速やかに削除する。
- 取引の連絡・評価は当事者のみ読み書き可能。
- 権限ルールは自動テスト(エミュレーター上のテスト)で「見えてはいけないものが見えない」ことを確認してから公開する。
- 不正なアプリからのアクセスを減らす仕組み(例:Firebase App Check)を導入。

## 5. 写真・位置情報・個人の特定
- 写真の位置情報(EXIF等のメタデータ)は、端末側に加えサーバー側でも必ず削除してから保存・公開する(端末側だけに頼らない)。
- 公開前に「窓の外の景色・郵便物・表札など、住所が分かるものが写っていないか」を注意喚起。
- 地域の表示は都道府県・市区町村の大まかな単位まで。詳細な住所・最寄り駅などは持たない。
- 手渡しの受け渡し場所は、公共の場所(イベント会場周辺・駅など)を案内し、自宅での受け渡しは推奨しない。
- プロフィールに載せる SNS・YouTube のリンク(2026-09-26 追加):
  - 載せるかどうかは本人が選ぶ。初期は非公開。SNS を載せると本名・住まいなどが特定され、盗難につながりうることを、載せる画面で注意する。
  - 載せられるのは、https で始まる、決めたサービスのドメインだけ(例:Instagram・X・YouTube)。それ以外のリンク、短縮 URL、`javascript:` などは拒否する(フィッシング・悪質サイトの対策)。許可するドメインの一覧はステップ3の設計で決める。
  - 公開用のデータ(`publicProfiles`)には、サーバーだけが書き出す。非公開のデータと同じ文書に混ぜない。
  - 外部のサイトへ移る前に「アプリの外に移動します」と表示する。
  - 実装時は、権限ルールの変更に合わせて「非公開のリンクが他人に見えない」「許可していないドメインは保存できない」テストを追加する。

## 6. 取引・コミュニケーションの安全
- 通報・ブロック・禁止ワード・評価を最初から実装。
- 取引の連絡はアプリ内で行い、電話番号・住所などの交換は取引成立後、本人が必要な範囲で行う形にする(発送時の住所の扱いは、匿名配送などの仕組みも将来検討)。
- 未成年の利用方針(年齢制限・保護者の同意・取引の制限)を規約で決める。
- 詐欺・なりすまし対策:記録の継続期間・評価・回答実績の表示、同一端末での複数アカウントの監視。プロフィールのリンクは「本人が申告したリンク」であり、そのアカウントが本人のものかは確認できない。「本人確認済み」とは表示しない。
- 相談の回答で危険な内容(農薬の誤用・有毒植物の扱い等)は通報・削除の対象にする。

## 7. 決済
- カード情報をアプリ・自前のサーバーで扱わない。
- 有料プラン(デジタルの機能)はApp Store/Google Playのアプリ内課金を使う(ストア規約上、デジタル機能の販売はアプリ内課金が原則)。
- 植物・資材の売買の自前決済は、法務確認(資金決済法等)と決済代行サービスの利用を前提に後から導入。それまでは当事者間の手渡し・外部サービス。

## 8. AI(相談の一次回答・イベントと入荷情報の収集)
- AIに送るのは、質問と本人が添付を選んだ記録のみ。非公開の記録を本人の同意なく送らない。
- 利用するAIサービスの「入力データを学習に使うか・保存期間」の設定を確認し、学習に使われない設定を選ぶ。
- 利用規約・プライバシーポリシーでAIの利用を明示。
- イベント・入荷情報の収集(2026-09-26 追加):
  - 収集に使うのは、店・主催者の公式サイトなど、公開されているページだけ。利用者の情報(非公開の記録・アカウント情報)はAIに送らない。
  - SNS(Instagram など)の自動収集はしない(各サービスの規約)。他サイトの文章は転載せず、事実だけを載せて出典リンクをつける。
  - 確度の高い情報だけを載せる。出典リンクと確認日を表示し、「違っていた」の報告を受け付け、誤りは速やかに訂正・削除する。
  - ワシントン条約の対象、盗掘株、特定外来生物にあたる情報は載せない(`concept.md` ⑥の懸念点と同じ)。
  - AIサービスの学習・保存の設定は、相談の一次回答と同じく確認する。

## 9. 個人情報保護・法令・ストア
- プライバシーポリシーを作成・公開(App Store・Google Playの提出にも必要)。利用目的、第三者提供(広告・分析・AI・決済サービス等)、保存期間、削除方法を明記。
- 個人情報保護法への対応:利用目的の特定と通知・公表、安全管理措置、第三者提供の扱い。漏えい等が起きた場合、一定の場合は個人情報保護委員会への報告と本人への通知が義務(2022年4月の改正法施行以降)。
- ストアのプライバシー表示(App Storeのプライバシー情報、Google Playのデータセーフティ)を正確に記載。広告SDKが収集するデータも含める。
- 広告の配信で個人を追跡する場合の同意取得(iOSのATT等)を確認。
- 利用規約:禁止事項(特定外来生物の譲渡、違法・危険な出品、なりすまし等)、トラブル時の方針、免責。

## 10. 開発・運用
- APIキー・秘密鍵をアプリのコードやリポジトリに含めない(秘密情報の管理機能を使う)。
- 依存ライブラリ・SDKを定期的に更新し、既知の脆弱性を確認。
- 通信はすべて暗号化(HTTPS)。
- 管理者権限は最小限(開発者本人のみ、二段階認証必須)。
- 操作ログ・不審なアクセスの監視、データのバックアップ。
- 事故対応の手順を事前に用意(検知 → 影響範囲の確認 → 公開停止 → 本人への通知 → 必要に応じて個人情報保護委員会へ報告 → 再発防止)。
- 大きな機能追加の前に、セキュリティの確認項目(本ドキュメント)に沿って点検する。

| フェーズ | 必須のセキュリティ要件 |
|---|---|
| 1(プロトタイプ・自分とテスター) | 認証、デフォルト拒否の権限ルールと自動テスト、写真の位置情報のサーバー側削除、公開用データの分離、アカウント削除、秘密情報の管理、プライバシーポリシー・利用規約の初版 |
| 1.5(同居人共有・有料プラン) | 招待リンクの期限・解除、アプリ内課金、共有範囲の権限テスト |
| ステップ2(入荷情報・イベントの掲載。旧呼び方なし) | 収集元は公開ページだけ、出典と確認日の表示、誤りの報告と訂正・削除、違法な株・外来生物の除外、AIの学習設定の確認 |
| 2a(記録の閲覧) | 植物ごと・項目ごとの公開設定の反映、公開取り消し時の削除、通報・ブロック、プロフィールのリンクの扱い(許可ドメインだけ・本人が選んだ場合のみ公開・権限テスト) |

| 2b(売買・交換) | 取引連絡の当事者限定、評価、禁止出品、受け渡し場所の案内、未成年の方針 |
| 3以降 | イベント参加者表示の本人許可、店舗掲載の審査、自前決済の法務対応 |

# RootLog(仮名)ステップ0 設計書(2026-09-25 初版・レビュー反映済み)

対象:ステップ1「記録と来歴」を作るための設計。確定事項は「植物アプリ_開発の決め事」、セキュリティは「植物アプリ_セキュリティ要件」に従う。
技術:Flutter+Firebase(Authentication / Firestore / Cloud Storage / Cloud Functions 第2世代 / App Check / Analytics)、リージョンは東京(asia-northeast1)。

## 1. データ設計

### 1.1 基本方針
1. 非公開データはすべて `users/{uid}` の下に置き、本人だけが読み書きできる。
2. 公開用のデータは別の場所(`publicPlants` / `publicProfiles` / Storage の `public/`)に、サーバーだけが「公開を選んだ項目だけ」書き出す。非公開の項目と公開の項目を同じ文書に混ぜない。
3. 来歴の元になる「写真の記録」はアプリから作れない。サーバーが受信時刻で作り、後から変更できない。
4. 課金状態(`plan`)、年齢区分(`ageBand`)、来歴の印(`hasProvenance`)など、信頼に関わる項目はアプリから変更できない。
5. 位置情報は取得しない。地域は都道府県コードまで。置き場所は名前だけ(住所は持たない)。

### 1.2 Firestore の構造
| パス | 内容 | 読める人 | 書ける人 |
|---|---|---|---|
| `users/{uid}` | 表示名、年齢区分(13-17 / 18+)、好きなジャンル、都道府県、通知設定、課金状態 | 本人 | 本人(課金状態・年齢区分は不可)/サーバー |
| `users/{uid}/plants/{plantId}` | 名前、ジャンル、品種、入手日、入手先、置き場所名、鉢の号数、タグ(復活チャレンジ・実生)、公開設定、来歴の印 | 本人 | 本人(来歴の印は不可、作成時は必ず非公開)/サーバー |
| `…/plants/{plantId}/logs/{logId}` | 水やり・植え替え・肥料・剪定・メモ・段階(入手・発根・新芽・植え替え・開花・株分け・復活・枯死) | 本人 | 本人(記録時刻はサーバー時刻で固定、未来の日時は不可) |
| `…/plants/{plantId}/photos/{photoId}` | 保存先、サイズ、撮影元(camera / gallery)、受信時刻、来歴かどうかと理由、画像のハッシュ、重複元 | 本人 | サーバーのみ |
| `…/plants/{plantId}/systemLogs/{id}` | 写真の削除など、来歴の欠落の記録 | 本人 | サーバーのみ |
| `publicPlants/{uid}_{plantId}` | 公開を選んだ植物の、選んだ範囲だけ(写真のみ/履歴まで/入手先まで)。IDに所有者を含め、他人の公開データを上書きできないようにする | ログインしている人 | サーバーのみ |
| `publicProfiles/{uid}` | 公開プロフィール(ステップ3) | ログインしている人 | サーバーのみ |
| `photoHashes/{sha256}` | 写真の使い回しの検出用 | なし | サーバーのみ |

### 1.3 Cloud Storage の構造
| パス | 内容 | 読める人 | 書ける人 |
|---|---|---|---|
| `uploads/{uid}/{uploadId}` | アップロードされた元画像(位置情報を含みうる)。処理後すぐ削除 | なし | 本人(作成のみ、JPEG/PNG、15MB未満、植物IDと撮影元の指定が必須) |
| `photos/{uid}/{photoId}.jpg` | メタデータを削除・縮小した画像(無料:長辺1600px、有料:長辺3000px) | 本人 | サーバーのみ |
| `public/{uid}/{photoId}.jpg` | 公開を選んだ植物の写真のコピー | ログインしている人 | サーバーのみ |

### 1.4 来歴写真の仕組み
1. アプリ内カメラで撮影 → すぐにアップロード(撮影元 `camera`)。端末の写真から選んだ場合は `gallery`。
2. サーバー(`processUpload`)が、元画像の撮影時刻(EXIF)を読み取る。撮影時刻は判定にだけ使い、保存しない。
3. 位置情報を含むメタデータをすべて削除し、縮小して `photos/` に保存。元画像はすぐに削除。
4. 「写真の記録」をサーバーの受信時刻で作成。来歴として認めるのは、次をすべて満たす場合。
   - 撮影元が `camera`
   - 撮影時刻(EXIF の撮影日時。編集日時は使わない)と受信時刻の差が10分以内(撮影時のタイムゾーン情報があれば正確に判定、なければ1時間単位のずれを許容)
   - 同じ画像が他に登録されていない(画像のハッシュで照合)
5. 本人が写真を削除すると、`systemLogs` に「削除された写真あり」の記録が残る。取引で相手に見せるとき、来歴に欠落があることが分かる。

限界(正直に書いておく点):
- 撮影元 `camera` と EXIF の撮影日時は端末側の情報。改造したアプリなら偽装できるため、App Check を有効にして減らすが、完全には防げない。確実に保証できるのは「サーバーが受信した時刻」であり、画面では「この日時までに撮影された写真」と表示する。
- タイムゾーン情報がない写真は1時間単位のずれを許容するため判定が甘くなる。30分・45分単位のタイムゾーン(インド等)は判定できない。
- 別の株を撮影して来歴として登録することは防げない。評価・通報と、長期間の記録の積み重ねで信頼を補う。
- 画像のハッシュは完全一致の検出だけ。加工した写真の使い回しを見つける仕組み(似た画像の検出)は将来検討。

### 1.5 サーバー処理(Cloud Functions)
| 処理 | きっかけ | 内容 |
|---|---|---|
| `processUpload` | `uploads/` への保存 | 実際の画像形式の確認(JPEG/PNGのみ、4,000万画素まで)・メタデータ削除・縮小・来歴判定・写真の記録の作成・元画像の削除。1インスタンスで1枚ずつ処理 |
| `deletePhoto` | アプリから呼び出し(App Check 必須) | 写真と公開コピーの削除、来歴の欠落の記録 |
| `onPlantDeleted` | 植物の削除 | 写真・記録・公開用データの後片付け |
| `onPlantWritten` / `onPlantLogWritten` | 植物・記録の作成・更新(写真の追加・削除時も呼び出す) | 毎回データベースを読み直して、公開を選んだ植物だけ選んだ範囲を `publicPlants` に書き出し。書き込む直前に「まだ公開か」を確認し、非公開に戻したら公開用データと写真を削除 |
| `deleteAccount` | アプリから呼び出し(App Check 必須) | 公開用データ・写真・記録・ログイン情報をすべて削除 |

### 1.6 自動テスト(権限ルール)
- `tests/firestore.rules.test.ts`:本人以外が読めない、公開状態での新規作成ができない、課金状態・年齢区分・来歴の印を変更できない、記録時刻を偽れない、写真の記録をアプリから作れない、公開用データを直接書けない、名前の文字数の数え方(絵文字は2文字分)など44件。
- `tests/storage.rules.test.ts`:他人の場所にアップロードできない、画像以外は不可、元画像は本人も読めない、処理済みの写真は本人だけ、公開写真はログインしている人だけ、など14件。
- 実行:`npm install` → `npm test`(Firebase エミュレーター上で実行。Java 11以上が必要)。

## 2. ステップ1の画面設計
※ 2026-09-26 以降の変更(ゴースト表示・巡回モード・タイムラプスの後回し、写真のダウンロードの追加など)は、`docs/spec/` が正。この章は初版のまま残している。

### 2.1 画面一覧
| # | 画面 | 主な要素 |
|---|---|---|
| 1 | ようこそ | アプリの説明(記録・来歴・非公開が初期設定であること)、Apple/Googleでサインイン |
| 2 | 年齢の確認 | 13歳未満は利用不可の案内。13〜17歳/18歳以上を選択(後から変更不可。売買・交換は18歳以上) |
| 3 | 好きなジャンル | 観葉植物全般(パキラ・モンステラ・ポトス等)・塊根・アガベ・多肉/サボテン・ビカクシダ・アロイド・珍奇植物・実生・その他から複数選択 |
| 4 | ホーム(植物リスト) | 置き場所ごとのまとまり、各株の最新写真と「前回の撮影から○日」、来歴の印、上部に「巡回する」ボタン、右下に「株を追加」 |
| 5 | 株を追加 | 名前・ジャンル・品種・入手日・入手先(非公開と明記)・置き場所・鉢の号数・タグ(復活チャレンジ/実生)。保存後すぐ最初の撮影へ |
| 6 | カメラ | 前回の写真を半透明で重ねる(ゴースト表示)、撮影ボタン、撮影後に「1週間前・1か月前」との比較。端末の写真から選ぶ場合は「来歴にならない」と表示 |
| 7 | 巡回モード | 置き場所の順に株を1つずつ表示 → 撮影 → 「水をやった」1タップ → 次の株へ。最後に完了画面 |
| 8 | 株の詳細(栽培ストーリー) | 写真と記録の時系列、段階タグ、タイムラプス再生、来歴の写真に印、削除された写真の表示、記録ボタン(水やり・植え替え・肥料・剪定・メモ・段階) |
| 9 | 共有設定(株ごと) | 公開/非公開、公開範囲(写真のみ/履歴まで/入手先まで)。ステップ1では「公開はステップ3で使えるようになります」と表示し、設定だけ保存 |
| 10 | 通知の許可 | 最初の撮影のあとに「来週また撮る日を知らせますか?」。選ばなければ通知はオフのまま(オプトイン。2026-09-26)。オンにした人だけ、撮影通知の頻度(週1が初期値)と時間を選ぶ |
| 11 | 設定 | 通知の種類ごとのオン/オフ(撮影通知・水やり通知はどちらも初期オフ)、プライバシーポリシー、利用規約、アカウント削除 |
| 12 | アカウント削除 | 削除されるものの説明 → 確認 → 削除 |

### 2.2 主な流れ
- 初回:ようこそ → サインイン → 年齢の確認 → 好きなジャンル → ホーム(空の状態で「最初の株を追加」)→ 株を追加 → カメラ → 撮影後の比較 → 通知の許可 → ホーム
- 週1回の撮影:撮影通知(オンにした人だけ。オフの人はホームやウィジェットから開く)→ 巡回モード(カメラが直接起動)→ 全株を撮影・水やり記録 → 完了(今週の変化の一覧)
- 記録:ホームで株を長押し → 「水をやった」、または株の詳細の記録ボタン

### 2.3 画面設計のルール
- ホームは植物リストと撮影を中心にし、機能を詰め込まない。
- 公開に関わる操作には、必ず「誰に何が見えるか」を表示する。
- 撮影から保存までの間に広告を入れない(ステップ1は広告なし)。
